# The next host direction: a declarative NixOS box (Bas Nijholt's model)

Source: Bas Nijholt, "My declarative multi-machine homelab, explained" (2026-09-28, updated 2026-10-09),
https://www.nijho.lt/post/homelab-explained/ . His config is public: the dotfiles repo (`configs/nixos`) and
compose-farm (`cf`). The user chose this model over Proxmox on 2026-10-28; the host itself stays plain Ubuntu until a
NixOS trial in a VM on this box passes (dev-system `migrations/ubuntu-native/MIGRATION.md`, "Later, not now").

## His model in one paragraph

Four machines, all NixOS, each machine's whole config in one public git repo. `comin` on every machine pulls `main`,
builds and switches, and deploys only commits signed with his SSH key. About 150 Docker Compose stacks, upstream
files almost unchanged, live in one repo mounted at `/opt/stacks`; `compose-farm` maps each stack to a host and runs
plain `docker compose` there over SSH. Data is bind-mounted from `/mnt/data/<stack>`, one ZFS dataset per stack with
snapshots every 10 minutes. One Traefik is the only listener on 80/443; private is the default (an IP allowlist
middleware) and a route is public only when it names the `wan` entrypoint. Remote access is self-hosted Headscale
plus WireGuard on the router as a way in that does not depend on the lab. A dead machine comes back by installing
NixOS and pointing it at the same config.

## What maps onto this box (one PC plus the Synology NAS)

| His piece | Here today | Verdict for the NixOS trial |
|---|---|---|
| NixOS config in git, rebuild = install and point at it | Ubuntu plus the manual `REBUILD.md` and `host/` scripts | **The core of the move.** Each `host/` unit, timer and script becomes a Nix module; `REBUILD.md` shrinks to the bootstrap. |
| `comin`, signed commits only | the agent runs commands on the box | **Candidate.** Agents edit the config repo; the box applies only commits the user signed. |
| Everything as a file, so agents work on diffs and `git revert` | apps, dev-system and FLEET.md already are | Same principle; keep it. |
| Bind mounts at `/mnt/data/<stack>` instead of named volumes | named volumes (FLEET.md) | **Open:** he lost named volumes to a prune once. Measure our prune risk (`fleet-ops`) before changing. |
| ZFS dataset per stack, 10-minute snapshots | btrfs subvolumes plus Timeshift; app data off the system rollback | Same idea with btrfs; per-app dumps to the NAS stay the backup. |
| Most images on `latest` | every image pinned to a patch (Part 1, invariant 2) | **Keep our pins.** A moving tag rebuilds differently on a new host. |
| `compose-farm`, Incus, stacks moved between hosts | one PC | Not needed with one host. |
| Traefik as the one front door, Headscale, router WireGuard | one Tailscale sidecar per app, no host ports (invariant 6) | **Not now.** The sidecars work and need no public login server; revisit only with a second host. |
| "Generate what you can; hand lists drift" | FLEET.md generated by `fleet-facts.py` | Already the rule. |
| `AGENTS.md`: "NEVER run docker compose directly", use the wrapper | agents run `docker compose` per the app's Commands block | Only worth it with a wrapper; not with one host. |

## Gotchas he hit that would bite here too

- Tailscale on a NixOS host that routes for containers needs `--snat-subnet-routes=false`, or requests arrive from
  the Docker bridge gateway (a `172.x.0.1` address) and fail an IP allowlist.
- Phones may not resolve `.local` or `home.arpa` names from regular DNS (Chrome searched Google instead).
- Test every way in after a network change: home, the tailnet, and from outside (expect a refusal for private names).
